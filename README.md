# RAG Document Q&A

A minimal **Retrieval-Augmented Generation (RAG)** tool that answers questions about a small set of documents — with chunk citations for every answer, and an honest **"I don't know"** whenever the documents don't contain the answer.

> Elevvo Internship — Python Programming & AI Track · **Task 7: LLM-Powered Document Q&A Tool (RAG Basics)** (Module 8: Building LLM-Powered Applications)

## What it does

1. **Indexes** every `.txt`/`.md` file in `data/` (4 sample documents are included).
2. Splits each document into **fixed-size chunks** (500 characters, 50-character overlap, word-boundary aware).
3. Embeds every chunk with the **free, local** `sentence-transformers` model `all-MiniLM-L6-v2` — no API key, and no document ever leaves your machine.
4. Stores the embeddings in a **FAISS** vector store (inner product over normalised vectors = cosine similarity).
5. For a question, retrieves the most similar chunks, checks them against a **configurable similarity threshold**, and only then generates an answer — **citing the chunks it used**.

### The threshold is enforced in code, not in the prompt

If the best chunk scores below the threshold (default `0.35`), the tool answers **"I don't know"** and the LLM is never even called. The threshold can be changed in code, with the `--threshold` flag, with the `RAG_SIMILARITY_THRESHOLD` environment variable, or with the slider in the web UI.

### Answer generation

- With `OPENAI_API_KEY` set: answers are generated by the OpenAI API (the Module 8 approach), grounded strictly in the retrieved chunks.
- Without a key: an **offline extractive fallback** returns the best-matching chunk as the answer, clearly labelled — so retrieval, thresholding and citations can be run and tested end to end with zero setup.

Only the sample/public documents in `data/` are used — never private files.

## Features

- Fixed-size chunking with overlap and stable chunk IDs (`source#index`)
- Local embeddings (sentence-transformers) + FAISS similarity search
- Configurable similarity threshold with a tested "I don't know" path
- Chunk-level citations with similarity scores on every answer
- CLI (one-shot and interactive modes) **and a Streamlit web UI (bonus)**
- Pytest suite covering chunking, the vector store, threshold behaviour and citations

## Tech stack

- Python 3.10+
- `sentence-transformers` (all-MiniLM-L6-v2) — local embeddings
- `faiss-cpu` — vector store / similarity search
- `openai` — answer generation when a key is configured
- `streamlit` — web interface (bonus)
- `pytest` — tests

## Setup

```bash
git clone https://github.com/MaryammMalik/rag-document-qa.git
cd rag-document-qa
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

The embedding model (~90 MB) downloads automatically on first run and is cached afterwards.

### Optional: enable OpenAI answers

```bash
cp .env.example .env
# OPENAI_API_KEY=your_openai_api_key_here
```

## How to run

```bash
# One-shot question
python -m rag_qa "When is the deadline for the one-month internship?"

# Interactive mode
python -m rag_qa --interactive

# Custom threshold / your own documents
python -m rag_qa "What is chunking?" --threshold 0.45 --docs ./data

# Web interface (bonus)
streamlit run app.py
```

## How to run the tests

```bash
pip install -r requirements-dev.txt
pytest
```

The 11 tests use a deterministic test embedder and a fake generator, so they run offline in under a second — including proof that the generator is **never called** when the best chunk is below the threshold.

## What I learned

- How RAG grounds an LLM in real documents: chunk → embed → retrieve → generate, and why each stage matters.
- Why embeddings and cosine similarity work for semantic search — a question and its answer rarely share exact keywords, but their vectors end up close.
- That "I don't know" is a feature, not a failure — and that a threshold enforced in code is reliable in a way prompt wording alone never is.
- How much retrieval quality depends on chunking: size, overlap, and clean boundaries change which answers the tool can find.
